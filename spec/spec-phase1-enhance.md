# spec‑phase1‑enhance.md

## 阶段前提

> 本阶段依赖Phase0全部代码底座。Phase0必须完整可运行，主控与4个子Agent调度流程全部正常。
> 本阶段**禁止修改原有Agent架构、禁止增删Agent角色、禁止改动LangGraph整体流程图结构**。
> 不做Web页面、不做HTTP接口、不接入真实外部API、不做数据库持久化。

## 阶段目标

在Phase0现有代码基础上增强各个子Agent的推理能力：
子Agent不再返回固定写死的静态mock数据，能够读取全局state中的用户参数（目的地、天数、出行时间、预算上限、用户偏好），**动态推理生成贴合用户条件的模拟旅行信息**。

示例：
用户输入：“去巴黎玩5天，预算有限，喜欢博物馆”

- 机票Agent：给出经济舱模拟方案，而不是固定商务舱
- 酒店Agent：输出经济型酒店模拟选项
- 活动Agent：优先输出博物馆相关行程
- 预算Agent：校验总开销是否超出用户预算上限，给出超支提醒

## 技术栈与依赖约束

沿用phase0锁定的全部依赖版本，**不升级主版本、不新增任何外部npm包**。
仅允许调整提示词、state类型、Agent内部业务逻辑。

## 需要扩展修改点

### 1. 修改 src/state.ts 全局状态

在原有state基础上扩展字段：

- user_preference：用户偏好（美食/自然风光/博物馆/亲子等）
- budget_limit：用户设置预算上限
- travel_style：出行风格（穷游/舒适/轻奢）

> 注意：原有state字段全部保留，只增量扩展，不删除phase0已有的状态定义。

### 2. 增强各个子Agent

1. FlightSearchAgent
   读取用户预算、出行时间，动态生成匹配舱位、时间段的模拟机票方案。
2. HotelBookingAgent
   读取预算、出行风格，输出对应档次酒店模拟选项。
3. ActivitiesAgent
   读取用户偏好，优先生成匹配兴趣点的游玩行程。
4. BudgetingAgent
   新增能力：汇总各项开销，对比用户budget_limit；如果预估总花费超出预算，输出预算告警提示，给出调整建议。

> 所有输出依旧是模拟数据，**严禁调用真实网络API**。

### 3. Supervisor（主控Agent）增强

1. 接收用户完整输入之后，解析提取：目的地、天数、出行时间、预算上限、用户偏好。写入graph state。
2. 任务分发逻辑不变，依旧调用4个子Agent。
3. 汇总阶段：把预算Agent的超支判断、告警信息合并进最终旅行报告。

### 4. CLI命令行入口 src/index.ts

命令行交互增强：支持接收预算、偏好参数。
依旧为终端命令行程序，不做GUI。

## ✅本阶段必须交付

1. 原有Phase0全部功能保留可用；
2. 用户不同的预算、偏好输入，能够产出差异化的模拟旅行方案；
3. 预算Agent具备预算校验、超支提醒能力；
4. 整体链路完整运行无报错。

## ❌Phase1【禁止清单】

1. ❌禁止新增任何Agent角色，禁止修改多Agent调度架构
2. ❌禁止开发Web服务、网页UI、接口服务
3. ❌禁止接入真实机票、酒店第三方API，全部为模拟推理输出
4. ❌禁止数据库、文件持久化保存计划，全程内存运行
5. ❌禁止新增npm依赖包
6. ❌禁止大规模重构phase0已经稳定的graph调度代码，只做增量修改
7. ❌禁止实现用户账号、配置文件系统

## 工作流强制规则

1. 所有修改遵循增量开发，优先复用Phase0代码，不删除原有可用逻辑；
2. 修改完成之后，保留phase0原有测试用例输入，保证老场景依旧正常工作；
3. 任何想要超出本Spec范围的改动，停止开发，等待确认。
